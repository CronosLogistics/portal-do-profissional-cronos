## Server integration rules (src/lib)
- Insider image paths are collected centrally for every banner, event and portrait and validated against the edition ID in both the server function and database; missing banner overrides keep original assets. Why: monthly visual changes remain private and backward-compatible.
- The Insider carousel RPC temporarily prioritizes the verified official-presentation edition without changing its publication date, still enforcing audience, archive and expiry; other editions retain the three-Brazil-day window. Why: restore the presentation without expanding general visibility.
- Notification RPCs project current celebrations with separate per-user mural reads, without creating duplicate announcements. Why: preserve original posts and mandatory acknowledgment rules.
- EditorTexto shares formatting and link dialogs across announcements and reward programs; reward display sanitizes allowlisted HTML and preserves legacy plain text. Why: safe, consistent rich-text rendering.
- Vacation consultation filters active collaborators by nonblank SharePoint vacation-week status server-side and substitutes the extra-days return when populated; it never exposes HR notes or entitlement data. Why: show scheduled absences without leaking personnel information.
- Daily Entra sync lives in `src/lib/entra-sync.server.ts` (pure rules in `entra-sync.rules.ts`), triggered by the managed schedule calling `/api/public/jobs/entra-sync` or an admin's `syncNow`; it matches by `entra_oid` (email only before linking), mirrors name/email/employee ID/accountEnabled, bans disabled accounts, and records the run (origin, who triggered it) in the singleton `status_sincronizacao`, guarded by a 10-minute `reservar_sincronizacao` lock. Why: Microsoft is the source of truth for professionals.
- Monthly praise compilation (D2): Power Automate POSTs `{mes_ano, html}` to `/api/public/compilado-elogios` with `X-Webhook-Secret` (secret `COMPILADO_WEBHOOK_SECRET`); `receber_compilado` (service_role only) stores the raw HTML in `compilados_elogios` (outside `avisos.mensagem`, so the sanitizer can't break it) and upserts one `tipo='compilado'` aviso per month; slide 4 reads `compilado_vigente()` (1 month) and the reader shows the HTML in a script-less sandboxed iframe. Why: keep the email's full layout safely.
- Praise (D1) reads SharePoint RQ0013 server-side only (`src/lib/feedback.server.ts`, 5-min cache), resolves AuthorLookupId through the site's User Information List with createdBy identity fallback, and filters in `feedback.rules.ts` by the caller's profile email: involved rows or rows where they are the GESTOR_CONSIDERACOES person; only `field_4 = 'Elogio - EL'`. Why: the browser never gets the token or other people's rows, and the author and manager come from SharePoint.
- OfficeContext resolves the caller's verified profile email through projected SharePoint corporate-person lookup and active status server-side, never localStorage. Why: display only the professional's actual office.
- Priority queries return the caller's own rows and, separately, rows of department-authorized subordinate emails from `meu_escopo_departamento` (excluding own rows; reports never inherit the leader's GP access); the nav badge counts own rows only. Why: leaders consult reports in a separate tab without inflating their personal count.
- People-management priorities use projected SharePoint fields and the department scope RPC for own/subordinate emails and Gestão de Pessoas membership; system admin alone never grants all RH rows. Why: department replacement must not preserve stale GP access through legacy profile names.
- Department sync reads projected Departamentos, Profissionais Brasil current-department lookup (hiring-department fallback only when empty) and corporate-person lookups server-side, applies profiles and leadership relations atomically through service-role-only RPCs, refreshes at login and daily Entra sync, and uses a persistent five-minute freshness/lease check. Why: transfers and new hires receive authoritative sector access without names, browser input or manual assignments defining privileges.
- Supervisor identity accepts scalar or multiple SupervisorLookupId values and legacy Supervisor lookup objects, deduplicating by verified corporate email and preserving level precedence. Why: Graph can return single-person fields without expanded person arrays.
- Manager feedback received uses a separate authenticated function: resolve Profissional_ID through Profissionais Brasil and its corporate-person lookup to the active caller's verified email; never match names or broaden by role, and render comments as plain text. Why: recipient privacy is separate from RH priority access and external HTML cannot execute.
- Manager feedback separates own received rows and hierarchy-scoped report rows derived server-side from the verified department snapshot, independently of priority permissions; direct leaders see coordinators (supervisors only without coordinators), coordinators see supervisors and ordinary reports, and supervisors see ordinary reports. The server returns actual report membership independently of feedback counts; only members with reports see tabs, initially on received feedback. Author tasks remain in priorities. Why: protect recipient privacy and avoid showing team controls to non-leaders.
- Priority category and group visibility uses the shared pure `temPendencias` predicate; consultation errors render independently of empty accordions. Why: hide empty navigation consistently without hiding integration failures.
- Questionnaire drafts live in owner-only `questionarios_rascunhos` (RLS: author + `formularios.gerenciar`), separate from published forms; Microsoft Forms import (PDF print or pasted text) is parsed server-side by AI into editable questions that are only validated on publish. Why: drafts never reach respondents and AI output is always human-reviewed.
- Internal questionnaires use permission-checked RPCs, separate participation and response tables, and server-only SharePoint writes with stable per-submission record keys and immutable answer question snapshots; anonymous projections omit identity and timestamps. Why: prevent duplicate submissions and protect anonymity without exposing integration credentials.
- Questionnaire deletion blocks new responses and sync via a persistent lease, removes only matching SharePoint record keys, then atomically removes local records; managers can retry incomplete deletion. Why: prevent orphaned answers and false success during external failures.

- GIFs come only from Giphy (public browser key in `src/lib/giphy.ts`); body `<img>` and comment `gif_url` are restricted to Giphy https URLs by both `limpar_html_aviso`/`gif_permitido` and `rich-text.ts`. Interactive common notices (`permite_interacao`) reuse avisos_comentarios/reacoes via `pode_interagir_compilado`; `avisos.interacao` is granted to system Administrators and named people in service-role-only `permissoes_individuais`. Why: individual grants survive department sync and arbitrary images can't be injected.
